# API Documentation

## Response Format

All API responses follow a standardized format with correlation IDs for tracking and debugging.

### Success Response

```json
{
  "success": true,
  "code": "SUCCESS",
  "message": "Request processed successfully",
  "timestamp": "2024-01-15T10:30:00Z",
  "correlationId": "a1b2c3d4-e5f6-4g7h-8i9j-0k1l2m3n4o5p",
  "data": {
    "id": "123",
    "name": "Sample Resource"
  }
}
```

### Error Response Formats

#### Validation Error (400 Bad Request)

When request validation fails, field-level errors are returned:

```json
{
  "success": false,
  "code": "VALIDATION_ERROR",
  "message": "Request validation failed",
  "timestamp": "2024-01-15T10:30:00Z",
  "correlationId": "a1b2c3d4-e5f6-4g7h-8i9j-0k1l2m3n4o5p",
  "errors": [
    {
      "field": "email",
      "message": "Email is required",
      "code": "FIELD_ERROR"
    },
    {
      "field": "phone",
      "message": "Phone must be a valid format",
      "code": "FIELD_ERROR"
    }
  ]
}
```

#### Resource Not Found (404 Not Found)

```json
{
  "success": false,
  "code": "RESOURCE_NOT_FOUND",
  "message": "Product with id 999 not found",
  "timestamp": "2024-01-15T10:30:00Z",
  "correlationId": "a1b2c3d4-e5f6-4g7h-8i9j-0k1l2m3n4o5p"
}
```

#### Conflict Error (409 Conflict)

```json
{
  "success": false,
  "code": "CONFLICT",
  "message": "A resource with this ID already exists",
  "timestamp": "2024-01-15T10:30:00Z",
  "correlationId": "a1b2c3d4-e5f6-4g7h-8i9j-0k1l2m3n4o5p"
}
```

#### Dependency Failure (503 Service Unavailable)

When external dependencies fail:

```json
{
  "success": false,
  "code": "DEPENDENCY_FAILURE",
  "message": "Database connection failed",
  "timestamp": "2024-01-15T10:30:00Z",
  "correlationId": "a1b2c3d4-e5f6-4g7h-8i9j-0k1l2m3n4o5p"
}
```

#### Server Error (500 Internal Server Error)

For unexpected errors, internal details are not exposed:

```json
{
  "success": false,
  "code": "SERVER_ERROR",
  "message": "An unexpected error occurred. Please contact support with correlation ID: a1b2c3d4-e5f6-4g7h-8i9j-0k1l2m3n4o5p",
  "timestamp": "2024-01-15T10:30:00Z",
  "correlationId": "a1b2c3d4-e5f6-4g7h-8i9j-0k1l2m3n4o5p"
}
```

## Correlation ID Tracking

Every response includes a `correlationId` in both the response body and the `X-Correlation-ID` header. This ID can be:

1. **Provided by the client** in the request header `X-Correlation-ID`
2. **Generated by the server** if not provided (UUID format)
3. **Retrieved from request attributes** by filters

Correlation IDs enable:
- Request tracing across microservices
- Log correlation for debugging
- Request identification for support

## Exception Hierarchy

The following custom exceptions map to standardized responses:

- `ValidationException` → 400 Bad Request
- `ResourceNotFoundException` → 404 Not Found
- `ConflictException` → 409 Conflict
- `DependencyFailureException` → 503 Service Unavailable
- Generic exceptions → 500 Internal Server Error

## Usage in Servlets

```java
public class SampleServlet extends SlingSafeMethodsServlet {

    @Reference
    private ExceptionHandlerService exceptionHandler;

    @Override
    protected void doGet(SlingHttpServletRequest request, SlingHttpServletResponse response) {
        try {
            String id = request.getParameter("id");
            if (id == null) {
                throw new ValidationException("ID parameter is required");
            }
            
            // Business logic
            Object data = fetchResource(id);
            if (data == null) {
                throw new ResourceNotFoundException("Resource", id);
            }
            
            ApiResponse<Object> apiResponse = ApiResponse.success(data, 
                exceptionHandler.getOrCreateCorrelationId(request));
            response.setContentType("application/json");
            response.getWriter().write(toJson(apiResponse));
        } catch (Exception e) {
            ApiResponse<?> errorResponse = exceptionHandler.handleException(e, request, response);
            response.setContentType("application/json");
            response.getWriter().write(toJson(errorResponse));
        }
    }
}
```

## Security Considerations

- Internal stack traces are **never exposed** in error messages
- Sensitive data (passwords, tokens, etc.) must **never** be logged or included in error responses
- Correlation IDs are safe to log and include in responses
- Error messages are user-friendly and non-technical for 5xx errors
